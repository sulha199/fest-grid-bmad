- (decision) Added EventInfo.postId (Section 4.1) linking an event to its source Post; clarified Post interface (Section 4.7) doc comment. Reason: EventInfo has no image field by design (PRD gap confirmed while creating implementation Stories 1.3b/1.2a) — an event's image resolves via this relation to Post.imageUrl, not a stored field on EventInfo.
- (decision) Added Schedule.eventId (4.4) and Post.accountId (4.7) back-references, closing FK gaps found during architecture review with Winston (same pattern as EventInfo.postId).
- (decision) Added User, Subscription, Favorite, CalendarEntry, Report, ApiKey, and DefaultLocationChangeRequest interfaces (Section 4) — entities implied by prose (3.2, 3.7, 3.9, 3.11) but never modeled. Found during architecture review with Winston.
- (decision) SocialMediaAccountProfile.defaultLocation is account-level (shared across subscribers), not per-subscription. Reason: extraction runs once per shared post (Tier 2 round-robin), so a per-user default would create ambiguity about which subscriber's value applies to the shared EventInfo.
- (decision) defaultLocation edits apply immediately (no pre-approval gate); moderators are emailed and can accept or revert via DefaultLocationChangeRequest in Moderator Tools (3.9.3). Reason: avoids blocking extraction on moderator latency while still giving moderators an audit/override path.
- (decision) Adopted soft-delete (deletedAt) convention for EventInfo, Favorite, CalendarEntry, Subscription, ApiKey instead of hard deletes, to preserve moderation/audit history. Detailed indexing strategy (partial indexes on deletedAt) deferred to project-context.md / architecture spine, not PRD-level.
- (event) PRD updated: Schedule.eventId, Post.accountId, EventInfo.deletedAt, SocialMediaAccountProfile.defaultLocation added; new interfaces User/Subscription/Favorite/CalendarEntry/Report/ApiKey/DefaultLocationChangeRequest (4.8-4.14) added; Section 3.7/3.9.3 prose updated for default-location moderation flow.
