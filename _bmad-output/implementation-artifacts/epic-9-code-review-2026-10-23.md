Method: `bmad-code-review`, 3 chunks (domain, backend, web/UI) x 3 layers (Blind Hunter, Edge Case Hunter, Acceptance Auditor) = 9 layers, all completed. Every `high` finding below was reproduced by running the code; findings were re-checked against `master` at `349f4f2e` (51 commits after the merges), and anything master already fixed was dropped (flat summary hiding the weekday under a `dateRange`; the nightly eval's retry/abort handling; `venueType` removal). ## Decision needed

- [ ] **D1 [high] Live extraction quality is poor and the nightly eval is red.** The only nightly run that reached real model output (run 39864337168, 22 Oct, `gemini-3.5-flash`) drifted on 5 of 9 fixtures and 4 of 6 metamorphic variants. Real responses: "jazz or blues in a cafe this weekend, not workshops" → `{"op":"AND","types":["WORKSHOP"]}` (the NOT is dropped and the excluded type is *included*); "tech meetups this month, not seminars" → `{"op":"AND","types":["GATHERING"]}` (date, category and NOT dropped); a 13-artist OR → artist names returned as caveats. Good news: Gemini accepts the unrolled response schema (no 400), so the "schema too large" worry is closed. Production default is `gemini-3.5-flash-lite` (`env.ts:220`), weaker than the eval's model. Also, the system prompt dropped the old out-of-vocabulary caveat guidance (price thresholds, room/floor, absolute dates, time of day) and never teaches CAP-7 phrasings ("rest of this month" = TODAY + span 1 MONTH); few-shot examples have no span, `temporalFilter` or weekday case (`build-filter-extraction-request.ts`). Options: (a) iterate prompt/schema against the eval with a real key, recommended; (b) raise `GEMINI_FILTER_MODEL`; (c) ship as is and track. Needs your call because (a)/(b) need the Gemini key and a cost choice.
- [ ] **D2 [medium] "Edit / Expand" and the search box for filters that cannot be flattened (OR/NOT).** `handleAIExpand` returns early when `ai_filter` is null/`{}` (dead button), and for a compound filter that does resolve it copies only keyword/types/categories and clears the AI params, so the list silently becomes unfiltered (`use-ai-filter.ts:207-221`, `:239`). Typed search is ignored under an expression. Options: (a) hide Expand for non-flat filters and AND the search text onto the expression (recommended); (b) keep Expand, convert best effort and show a notice; (c) leave as is.
- [ ] **D3 [low] Unresolved `accountId` leaf under OR/NOT.** `mapFilterLeaves` drops the leaf, which narrows `OR(@known, @typo)` to `@known` and, inside `NOT(AND(a, @typo))`, widens the exclusion to `NOT(a)`; the caveat ("events from all accounts are shown") is false in both cases and is emitted once per occurrence. Options: (a) an unresolved account matches nothing (keep OR/NOT semantics exact) with an accurate caveat, de-duplicated (recommended); (b) drop the whole enclosing OR/NOT and caveat that.

## Patch

High:
- [ ] **P1 Feed and account pages leak or invert results for a root OR/NOT/lone-keyword expression.** `buildFeedQueryCondition.ts:50-75` and `buildAccountEventsQueryCondition.ts:37-60` splice the base scoping into the compiled group, keeping the group's operator: OR becomes `isFromSubscribedAccount OR … OR filter` (every matching event in the DB), root `NOT(group)` becomes `{not,[base…, child]}` and `drizzle-where.ts:35` negates only `parts[0]`. Root cause includes the re-wrap guard `compile-filter-node.ts:179` (`!isGroupCondition(compiled)`), so `AND[keyword]` compiles to a bare `or` and is not deep-equal to the flat form (breaks 9.2 decision 6 parity). Fix: splice only into an `and` root, otherwise nest (`and[base…, filter]`); make `not` negate `and(...parts)`; fix the guard. Reproduced on master.
- [ ] **P2 Event loop hangs on an invalid leaf from the model.** `transform-gemini-response-to-filter-expression.ts:178-211` loops until valid, but a leaf failing the schema (e.g. `radiusMeters: 0`, which the flat transform lets through, and the response schema declares a bare INTEGER) never shrinks, so the loop never exits. Reproduced: `{expression:{location:{coordinates,radiusMeters:0}}}` ran past a 60 s cap. Fix: validate/drop each leaf with a caveat before the loop, add a no-progress break, add `minimum: 1` to the response schema and a `> 0` check in the flat transform.
- [ ] **P3 The transform throws on an ordinary prompt.** `NOT` over a multi-field leaf becomes `NOT(AND(l1,l2))`; inside a root AND that is depth 4 and the code throws "structurally impossible" (`:165-175`), a 500, e.g. "free events, not music festivals". Reproduced. Fix: degrade (drop with caveat, or keep the NOT over the first field) instead of throwing.
- [ ] **P4 A multi-field leaf under OR loses its internal AND.** "workshops in Sleman or concerts in Bantul" → `OR(WORKSHOP, Sleman, PERFORMANCE, Bantul)` with no caveat. Reproduced. Fix: wrap a multi-field leaf child in `AND` when its parent is an OR (trim/caveat if depth would be exceeded).
- [ ] **P5 A single weekday fails the whole `resolvePromptToEventFilter` mutation.** `EventFilter.dayOfWeek` is `[DayOfWeek!]` (`events.graphql:321`) but `flatFilterFromExpression` (`flat-filter-conversion.ts:119`) and the flat transform emit a bare string for one day; no type resolver wraps it and the `as` casts hide it. Verified with graphql-js: `Expected Iterable, but did not find one for field "EventFilter.dayOfWeek"`. Hits "events on Fridays", and any stored flat filter with a single weekday. Fix: always return an array from the field resolvers (and the mutation payload).
- [ ] **P6 "My AI Filters" page crashes on every saved row (gap in PR #77).** `ai-filters-content.tsx:195` renders the raw, null-padded `filter.expression`; `isFilterLeaf` sees the `op` key and `normalize` maps `null` children. Reproduced. Row click (`:96-98`) also writes the padded JSON, plus `ai_filter=null` for non-flat rows, into the URL, and drops `ai_caveats`. Fix: strip/validate through `stripNullNodeKeys`/`validateFilterNode` at the page boundary and make `renderFilterExpressionSummary` null-tolerant; build the URL from the stripped tree and omit `ai_filter` when null. Tests use un-padded fixtures, add a padded one.

Medium:
- [ ] **P7 One bad stored row breaks the whole list.** `resolveStoredFilter` throws on a stored `dateRange` with `spanAmount:null`/`spanUnit:null` (typed as allowed), `radiusMeters` 0/null, `dayOfWeek:[]`, a removed enum value or an out-of-bounds offset; `expression: FilterNode!` then nulls `myAIEventFilters`/`myWidgets` for that user. The legacy flat write paths (`saveAIEventFilter`, `createWidget`, `updateWidget`) store flat input unvalidated, so a client can create such a row (and a mutation that stores then fails on return invites duplicate retries). Fix: make the read path degrade (skip invalid leaves, flat fallback), accept `null` for the optional span fields in the schema, validate flat input on write.
- [ ] **P8 The validator accepts values the compiler cannot handle.** A leaf with an unknown `op` (`{op:'XOR',field:'isFree',value:true}`) is valid, gets stored, then the compiler throws `Cannot read properties of undefined (reading 'map')` — a permanently unusable saved filter/widget. A `keyword` of `"#"` or whitespace is valid but compiles to nothing, so `OR(type, keyword '#')` narrows and `NOT(keyword '#')` matches everything. `validateFilterNode` returns the raw candidate (`filter-node-schema.ts:252`), so unknown keys and junk `value` on group nodes are persisted to jsonb. All reproduced. Fix: reject unknown `op`, require a meaningful keyword, return the parsed (stripped) output.
- [ ] **P9 The Gemini transform drops input with no caveat.** Reproduced: `dateRange` with `offsetAmount: 120 DAY` (out of bounds) removes the whole date constraint, `types:['BOGUS']` vanishes, `NOT` carrying `children` or sibling fields loses them (the whole prompt then reads as empty), lowercase `op` is ignored, a leaf with both coordinates and `adminArea` silently loses the area. SPEC: unsupported fragments are "never silently dropped". A blank string in the model's own caveats also suppresses `EMPTY_EXPRESSION_CAVEAT` (`:214-221`). Fix: push a caveat for every dropped fragment; filter blank caveats before counting.
- [ ] **P10 The summary and flat projection misdescribe lossy ANDs.** `collectFlatLeaves` (`flat-filter-conversion.ts:105-125`) accepts an AND of leaves with a repeated field and keeps the last (`type[A] AND type[B]` renders "B"; `adminArea` + `proximity` renders only "in Sleman"), and `resolvedFilter`/`flatFilter` carry the same fabricated partial. Fix: return no flat form (fall to the tree renderer) when a field repeats or `location` would hold both keys. (The weekday-under-`dateRange` omission is already fixed on master.)
- [ ] **P11 NOT and NULL disagree across spec, SQL and the model prompt.** SPEC and `filter-vocabulary.md`: "NOT includes events with no value". SQL: only `ne`/`notIn` are null-inclusive; `NOT (withinRadius …)` on nullable latitude/longitude drops events without coordinates (`drizzle-where.ts:35`, 9.2 decision 3 accepted this against the SPEC). The model prompt (`build-filter-extraction-request.ts:33`) tells Gemini the opposite ("ALSO excludes events that have NO VALUE"). Fix: `NOT COALESCE((child), false)` in the `not` arm; correct the prompt sentence.
- [ ] **P12 The prompt rate limiter is not atomic and its env knobs misbehave.** `prompt-filter-rate-limit-store.ts:21-48` is read-then-write: two first-ever concurrent calls both insert and the second fails on the primary key (unhandled 500); N parallel calls at count c all pass. `PROMPT_FILTER_RATE_LIMIT_WINDOW_MINUTES=0` disables the limit and `…MAX_REQUESTS=0` still admits one request per window (`env.ts:233-244`, `prompt-filter-rate-limit.ts:37`). Fix: a single `INSERT … ON CONFLICT (user_id) DO UPDATE … WHERE` upsert returning allowed/denied; require both env values >= 1. (Check-before-key-lookup order is mandated by 9.8 AC and stays.)
- [ ] **P13 The Today/Upcoming toggle does nothing while an AI filter is active.** The expression branch of `buildEventsQueryCondition`/`buildFeedQueryCondition`/`buildAccountEventsQueryCondition` and Home/Favorites/Feed ignore the page-level `temporalFilter`, yet the toggle still renders and still re-fetches. Violates CAP-6 parity (9.4a decision 3 claims byte-identical). Fix: AND the toggle's condition onto the compiled expression. Related low: Home's flat fallback overwrites the AI filter's own `temporalFilter` (`home-content.tsx:236`).
- [ ] **P14 Public `Query.events(expression:)` can be used to amplify work.** `stripNullNodeKeys` and `walkNode` recurse the whole input before depth/size are checked and emit one issue (with a full path) per level. About 3000 nested NOTs (63 KB) produced a ~27 MB `BAD_USER_INPUT` message, and 30000 levels throw `RangeError: Maximum call stack size exceeded`. The query is unauthenticated and validates before auth. Fix: iterative pre-check that bails once depth or node count exceeds the limits, and cap the number of reported issues.
- [ ] **P15 The nightly drift check cannot see the feature's core risk.** `compute-golden-prompt-drift.ts` compares only the sorted set of leaf field names and caveat presence, so a lost NOT or OR→AND flip reports "no drift" (D1's `nesting-en-01` drifts only because other fields vanished). Also: header comment says `--filter @festgrid/backend` (real name `backend`, `run-golden-prompt-live-eval.ts:9`), the job has no `timeout-minutes` or `permissions:` block, and it is bound to `environment: production`. Fix: compare a canonical operator/polarity shape, correct the filter name, add `timeout-minutes` and `permissions: contents: read`.
- [ ] **P16 The empty extraction cannot be saved.** `resolvePromptToEventFilter` returns `{op:'AND',children:[]}` for an unmappable prompt (or when every account leaf is dropped); the overlay still offers "Save this filter", and `saveAIEventFilter`/`createWidget`/`Query.events` reject it with a raw "zero children" message. Fix: hide/disable Save when the expression has no leaves.
- [ ] **P17 Multi-weekday windows can expand into hundreds of OR terms.** `dateRange` TODAY + span 24 MONTH with all 7 weekdays compiled to 710 `EXISTS` terms per leaf (12 leaves allowed), reachable from the public query. Fix: cap the expanded terms (e.g. reject above ~100 with a caveat) or switch to a single weekday-in terminal (the plan §5 mitigation).

Low:
- [ ] **P18 `collectExactDates` still descends into `or` groups** (`resolvers.ts:3205-3225`): `OR(dateRange TODAY, keyword jazz)` pins one date and the calendar ORDER BY tie-break then misorders other-date rows (pagination can skip/duplicate). Skip `or` as well as `not`.
- [ ] **P19 `FilterHub` keeps `isSummaryExpanded` across summaries** (`FilterHub.tsx:85`): after one expand, every later long summary opens expanded; also "Show more" can appear when nothing is clipped. Reset the state when the summary changes.
- [ ] **P20 Flat-fallback fidelity.** A bad or truncated `ai_expression` silently falls back to the lossy flat filter ("All events" or a different filter, no notice); the flat selections in `mutations.graphql`/`queries.graphql` omit `dateRange.spanAmount/spanUnit`; `EventFilter` (output) has no `temporalFilter` so the flat projection drops it. Add the span fields and `temporalFilter`, and show a caveat when `ai_expression` is present but invalid.
- [ ] **P21 `apps/web/fix-codegen.js:119` FilterNodeInput patch is not idempotent**: the removal regex needs `{` + newline + `child?:` so it never matches the one-liner it prepends; a second run (or a changed key order) leaves two `export type FilterNodeInput` (TS2300). Reproduced by simulation; still present on master.
- [ ] **P22 Summary text details.** `.replace(token, userValue)` in `summary-clause-formatters.ts` interprets `$&`/`$'` in user text (keyword `Rock $' Roll` renders "Rock  Roll"); singular spans render "the next 1 weeks"/"extending 1 days" (plural-only unit labels); a zero-offset span drops the anchor ("rest of this month" reads "the next 1 month"). Use a function replacer, singular unit labels in en/id, and anchor-aware span wording.
- [ ] **P23 `createWidget` treats `filters: null` as absent (`== null`) but `updateWidget` rejects it (`!== undefined`)** (`resolvers.ts:2350` vs `:2388`); generated clients often send explicit nulls. Use `!= null` in both.
- [ ] **P24 Build-time guard for the hand-copied selection depth.** The 3-level `FilterNode` selection in `mutations.graphql` and `queries.graphql` is tied to `FILTER_NODE_MAX_DEPTH = 3` by convention only (the last level selects no `children`/`child`). Add a test asserting the selection depth equals the constant.
