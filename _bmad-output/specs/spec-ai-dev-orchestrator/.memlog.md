- (direction) Standalone local dev-tooling initiative, not a festgrid product feature; built with LangGraph (Node.js/TypeScript), routed through the user self-hosted 9Router gateway
- (decision) 9Router confirmed as decolua/9router: self-hosted OpenAI-compatible gateway at http://localhost:20128/v1, Bearer auth, provider-prefixed model IDs / user-defined combo aliases -- node model routing must use configured aliases, never literal model names
- (decision) HITL timeout escalation is email-only via a single env-configured address; Telegram dropped from scope
- (decision) v1 scope is a standalone sandbox: orchestrator operates only against a config-pointed local TARGET_REPO_PATH, not against this repo real _bmad-output artifacts (epics, story files, sprint-status.yaml); real-BMad-artifact integration deferred to a future phase
- (decision) Build order is full spec then architecture then epics/stories before any code is written
- (decision) Reviewer verdict fixed to three values APPROVE / AUTO_FIX / NEEDS_HUMAN against a fixed rubric (architectural deviation from spec, ambiguous or conflicting requirement, security-sensitive change, repeated failed AUTO_FIX); only NEEDS_HUMAN triggers HITL
- (capability) CAP-1 Planner/Architect node reads spec.md and decomposes it into architecture notes, constraints, epics, and user stories written to tasks_queue
- (capability) CAP-2 Complex Worker/Reviewer node implements complex algorithmic work and Drizzle DB schema migrations, and reviews any node output for alignment with spec.md, returning one of APPROVE/AUTO_FIX/NEEDS_HUMAN
- (capability) CAP-3 Speed Worker node implements standard boilerplate, UI components, and API routes from a queued story quickly, on a fast/cheap routed model
- (capability) CAP-4 Tester/Utility node runs build and test shell commands against TARGET_REPO_PATH, parses terminal output, classifies failures, auto-fixes basic lint issues, and prepares a report
- (capability) CAP-5 Dev-an-epic entry point autonomously drives the full loop (create story, implement, test, review) across every story in a named epic without a manual invocation per story
- (capability) CAP-6 Manual review orchestration lets the user trigger a review pass over an already-implemented epic and its stories independent of the dev-an-epic loop
- (capability) CAP-7 HITL node pauses the graph and prompts for terminal input whenever the Reviewer verdict is NEEDS_HUMAN or the Tester hits a blocking, unclassifiable failure
- (capability) CAP-8 Async timeout escalation sends a notification email to an env-configured address if a terminal HITL prompt goes unanswered within a configurable timeout, default 5 minutes, while the terminal keeps waiting for input
- (capability) CAP-9 Every node LLM call is routed through 9Router using an OpenAI-SDK-compatible client, with the model alias per node role resolved from configuration rather than hardcoded
- (capability) CAP-10 Orchestrator reads and writes files and executes shell commands only against a single config-pointed local target repo path, TARGET_REPO_PATH
- (constraint) Must run entirely locally in a Node.js/VS Code environment; no cloud orchestration or hosted multi-tenant service
- (constraint) All LLM calls must go through 9Router OpenAI-compatible endpoint with Bearer auth; model IDs resolved from configured aliases only, never hardcoded literal model names
- (constraint) v1 must not read or write festgrid real _bmad-output artifacts; operates only against TARGET_REPO_PATH
- (constraint) GraphState fields are fixed to spec, tasks_queue, current_code, terminal_output, error_status, human_feedback; no ad hoc state additions without revising this contract
- (constraint) HITL timeout escalation is email-only via one env-configured address; no other notification channel in v1
- (constraint) Reviewer verdict is constrained to exactly APPROVE, AUTO_FIX, or NEEDS_HUMAN; no free-form review outcomes
- (note) Non-goal: not a festgrid product feature, does not touch real BMad artifacts in v1
- (note) Non-goal: not a hosted or multi-user service; single local user, one target repo per run
- (note) Non-goal: does not build or host 9Router itself, assumes it is already running and configured
- (note) Non-goal: no Telegram or other chat-app notification channel in v1
- (note) Non-goal: no web or GUI HITL interface, terminal-only interaction in v1
