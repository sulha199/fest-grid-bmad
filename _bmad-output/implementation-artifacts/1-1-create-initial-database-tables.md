## User Story

**I want** to create the initial database tables for Events, Schedules, Users, Locations, and Subscriptions,

## Developer Context

### Architecture & Technical Requirements
- **Database Access (Drizzle ORM):** All database schemas **must** be managed code-first using Drizzle ORM TypeScript schema definitions inside `packages/database/schema.ts`.
- **Drizzle ORM Types:** When defining database schemas, **must** utilize PostgreSQL-specific data types directly imported from `drizzle-orm/pg-core` (e.g. `{ pgTable, uuid, text, integer, timestamp, index }`). Avoid generic defaults. Use `uuid` for primary keys.
- **Unique Identifiers:** All primary entity identifier fields (`id: string`) **must** be generated automatically as UUIDs by the PostgreSQL database (e.g., using `defaultRandom()`).
- **Events & Schedules:**
  - `events` and `schedules` require a `slug: string` property (initially autogenerated using Nano ID or similar).
  - You will need to implement `events`, `schedules`, `users`, `user_locations`, `subscriptions`, and `api_keys` tables.
  - Foreign key relationships must be accurately modeled (e.g., `schedules` references `events`, `user_locations` references `users`).
- **Timestamps:** Use `withTimezone: true` for all timestamp columns (as demonstrated by the existing `timestamps` helper in `packages/database/schema.ts`).
- **Database Environments (Local vs Production):**
  - **Local Development:** The project uses a local PostgreSQL database. The `DATABASE_URL` for local development is configured in `packages/database/.env` (e.g., `postgresql://postgres:postgres@localhost:5432/festgrid`). You should generate and run migrations against this local database during development via `pnpm run generate` and `pnpm run migrate`.
  - **Production (Supabase):** The application relies on Supabase (PostgreSQL) exclusively for production environments. To deploy migrations to Supabase:
    1. The production `DATABASE_URL` is obtained from the Supabase project dashboard (`Settings` -> `Database`).
    2. This URL is configured in the production environment variables (e.g., CI/CD secrets).
    3. The CI/CD pipeline runs `drizzle-kit` to apply the generated SQL migration files directly to the Supabase Postgres instance.
  - You must document this dual environment setup (Local Postgres vs Supabase Cloud) and provide explicit instructions (e.g., in a README in `packages/database` or update `SETUP_WALKTHROUGH.md`).

### Indexing Requirements
- **Database Indexing for Performance:** Based on `project-context.md`, frequently used columns in `WHERE` clauses **must** be indexed. Ensure you add basic indexes using Drizzle's `index()` for fields like `eventName`, `performers`, `location` (or equivalents in your schema), `types`, and `categories`.

### Existing Code Patterns
- `packages/database/schema.ts` currently contains a `healthCheck` table and a `timestamps` helper. Remove the `healthCheck` table as the actual domain tables are created.
- Reuse the `timestamps` helper for all new tables.

### Testing Requirements

- Ensure all schemas and relations are exported properly so they can be consumed by the domain package later.
