# 🎯 Story Context Quality & Compliance Checklist

## **🔥 CRITICAL MISSION: Structural and Gate Compliance**

You are an independent quality validator in a **FRESH CONTEXT**. Your mission is to **thoroughly review** a story file that was generated by the `bmad-create-story` workflow and **systematically verify** that it strictly adheres to the mandated structural and architecture-gate requirements.

Your purpose is to ensure the generated story does not deviate from the structural standards in `story-content-structure.md` and actually performed the gates required by `story-split-gate.md`.

### **🚨 CRITICAL COMPLIANCE CHECKS REQUIRED:**

You must verify the following criteria. If the story fails any of these, you must apply fixes to ensure compliance.

#### **1. Canonical Section Order & Presence**
The story must contain exactly these sections in this order:
- [ ] `# Story <epic>.<story>: <title>`
- [ ] `## Story Details`
- [ ] `## Story`
- [ ] `## Acceptance Criteria`
- [ ] `## Tasks / Subtasks`
- [ ] `## Dev Notes`
- [ ] `## Global Rules References`
- [ ] `## Implementation Plan (Rule-Compliant)`
- [ ] `## Pre-Coding Approval Gate`
- [ ] `## Testing Requirements`
- [ ] `## Deliverables Checklist`
- [ ] `## Out of Scope`
- [ ] `## Definition of Done`
- [ ] `## Completion Status`
- [ ] `## Dev Agent Record`

#### **2. Dev Notes & Architecture Gates**
- [ ] `## Dev Notes` MUST contain the `### Architecture & UX Gate Findings` subsection.
- [ ] The Gate Findings must either explicitly state "No gap found" or explicitly detail the gap found from Gate 1/2/3 evaluation.
- [ ] If a gap was found, it must be listed under `## Out of Scope` with a suggested prerequisite story key.

#### **3. Pre-Coding Approval Gate State**
- [ ] `## Pre-Coding Approval Gate` MUST exist and include a checklist.
- [ ] The explicit human approval state MUST be present and default to pending (e.g. `[ ] Explicit human approval state (Default: pending approval)`).
- [ ] Must contain a checklist item confirming Gate 1/2/3 prerequisites are done or the gap is accepted.

#### **4. Global Rules References**
- [ ] `## Global Rules References` MUST be present.
- [ ] Must explicitly reference `project-context.md`, `story-content-structure.md`, the architecture spine, and infrastructure docs.

#### **5. Implementation Plan**
- [ ] `## Implementation Plan (Rule-Compliant)` MUST be present.
- [ ] Must include File Change Plan, Rule Mapping, and Verification Plan.

### **🔬 FIXING DEVIATIONS:**

If any of the above elements are missing, out of order, or incomplete:
1. Re-format the document to strictly align with the 15-section canonical order.
2. Insert missing sections with their default required content.
3. Explicitly add the `### Architecture & UX Gate Findings` section to `## Dev Notes` if missing.
4. Ensure the Pre-Coding Approval Gate requires human approval.

Once structural compliance is verified and corrected, report completion.
