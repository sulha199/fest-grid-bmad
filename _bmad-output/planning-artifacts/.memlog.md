- (decision) AD-8 new rule 4 (mutation contract): soft-delete mutations take an explicit direction argument via a shared enum SoftDeleteAction { DELETE, RESTORE }, argument name 'action' (e.g. deleteUserLocation(id: ID!, action: SoftDeleteAction!): UserLocation), returning the affected row's own type so the client syncs its cache from the response rather than a bare boolean. The mutation validates the state transition -- DELETE requires the row currently active, RESTORE requires it currently soft-deleted -- and errors rather than silently no-op'ing on a mismatched call. Chosen over the implicit-toggle shape (server infers direction from current deletedAt state, no param) because the revised EXPERIENCE.md Soft-Delete-with-Undo pattern (2026-08-06) commits immediately at Trigger, making caller intent -- a fresh delete vs. reversing one just made -- meaningfully different information the server should not have to infer.
- (decision) toggleFavorite/toggleCalendarAddition (apps/backend/src/schema/resolvers.ts) are an accepted legacy exception to AD-8 rule 4 -- they pre-date the explicit-param convention, are already shipped/tested, and are functionally equivalent (implicit-toggle also achieves delete-then-undo). Not reconciled to the new shape. Every new/future soft-delete mutation (deleteUserLocation now; ApiKey/Subscription delete mutations later, Epic 3/4) must use the explicit-param shape.

- (decision) AD-9 Date/Week Selection UI Convention. Binds: any FestGrid UI that lets a user pick a calendar date -- currently Story 1.3g's manual week-picker (packages/ui/src/features/events/WeeklyCalendarView.tsx), and any future date-selection UI. Prevents: (a) a third-party date-picker dependency -- shadcn has no dedicated DatePicker, only the verified Popover+Calendar+Button composition, which is the only sanctioned base; (b) a hand-rolled calendar grid reimplementing Calendar/react-day-picker; (c) a second, independently-computed week/date-boundary calculation living inside any picker component -- boundary math has exactly one home, Story 3.7a's useWeeklyCalendarController (AD-6/AC7's getWeekStart/getWeekEnd). Rule: 1) Composition base -- every date-picker is Button(trigger)+Popover+Calendar, mode="single" unless a feature genuinely needs range/multi-select; never a hand-rolled grid or new npm date-picker dependency. 2) packages/ui/src/core/WeekPicker.tsx wraps Calendar with modifiers/modifiersClassNames to highlight the full selected week row; it takes onSelectWeek(date: string) and a required getWeekRange(date: Date): { start: Date; end: Date } prop supplied by the caller from Story 3.7a's exported getWeekStart/getWeekEnd -- WeekPicker never computes a boundary itself, so exactly one boundary implementation exists app-wide. 3) Future date-pickers reuse WeekPicker directly if week-range selection is needed again; otherwise compose Button+Popover+Calendar inline per rule 1. A pattern generalizes into a new packages/ui/src/core/ primitive only once a second real consumer exists -- matching the project's existing core/vs/features placement convention.
