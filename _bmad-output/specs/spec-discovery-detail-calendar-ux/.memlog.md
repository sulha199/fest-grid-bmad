- (direction) User requested three bundled brownfield UI enhancements to already-shipped Epic 1 components: compact dropdown FilterHub, carousel-based event-detail navigation with icon-only modal close, and calendar manual week-picker with Monday week start.
- (capability) CAP-1 FilterHub compact dropdown: intent - user operates Type/Category filters as compact dropdown triggers (shadcn Popover+Button) showing selection state (primary color) and a floating count badge, instead of always-expanded pill rows; success - trigger is variant=default with a small count badge when that facet's selection>0, variant=outline with no badge when empty, PopoverContent reuses existing toggle-list markup, and the filter bar lays out as a single flex-wrap row (type/category/location triggers + inline Clear-all) instead of a vertical stack.
- (capability) CAP-2 Event detail carousel-chrome navigation: intent - user moves to next/previous event in list context via shadcn Carousel visual chrome (arrows, optional swipe) wrapping the single currently-loaded EventDetailView, replacing the plain prev/next buttons; success - Carousel's controls invoke the existing handlePrevious/handleNext -> nav.requestNext()/router.replace flow, existing nav.previous.disabled/nav.next.disabled-or-loading states are preserved on the Carousel controls, and no second event's data is preloaded/mounted simultaneously.
- (capability) CAP-3 Icon-only modal close: intent - user closes the event-detail modal via an icon-only control with no visible text label, matching the existing shadcn DialogClose pattern (X icon + sr-only text); success - the modal close button in EventDetailWrapper.tsx renders only an X icon, aria-label and a sr-only span remain for accessibility, and the visible t('closeModal') text no longer renders.
- (capability) CAP-4 Calendar manual week picker: intent - user opens a popover date picker (shadcn Popover+Calendar) alongside the existing prev/next week buttons to jump the weekly view directly to an arbitrary week; success - selecting any date resolves to that date's week start using the same week-start rule as prev/next/today and calls the existing setWeek/onNavigate plumbing, with no divergent boundary calculation introduced.
- (capability) CAP-5 Monday week start: intent - the weekly calendar's week boundary changes from Sunday-Saturday to Monday-Sunday (ISO-8601 style), confirmed explicitly by the user, applying uniformly to prev/next/manual-pick/today; success - useWeeklyCalendarController's week-start calculation returns Monday for any input date, and existing Sunday-based test assertions in useWeeklyCalendarController.test.tsx are updated to match.
- (constraint) Carousel must not preload or mount more than one event's data at a time -- data is fetched per-slug via GraphQL on demand, so this rules out a true multi-slide Embla carousel; only the chrome/gesture layer is reused.
- (constraint) New shadcn primitives Popover, Badge, Carousel, and Calendar do not yet exist in apps/web/src/components/ui/ (only button/card/dialog/sheet/switch/table/select/radio-group/textarea are installed) and must be added via the shadcn CLI before use; Popover is a shared prerequisite for both CAP-1 and CAP-4.
- (constraint) Manual week-picker date selection (CAP-4) must resolve to a week boundary using the exact same week-start calculation as prev/next/today (CAP-5) -- no second, divergent boundary calculation.
- (constraint) Any visible string added, changed, or removed (e.g. the dropped close-button label) must route through next-intl per project-context.md's i18n rules; existing keys in apps/web/locales/{en,id}.json (closeModal, previous, next) must be checked for reuse vs orphaning rather than left dangling.
- (constraint) Reusable components follow the existing placement convention from project-context.md: feature components in packages/ui/src/features/<domain>/, framework-agnostic core primitives in packages/ui/src/core/.
- (constraint) Popover-based FilterHub dropdowns must use shadcn Popover, not DropdownMenu -- Radix DropdownMenu's menuitem semantics auto-close on item click and fight multi-select toggle-without-closing behavior.
- (non-goal) Not introducing a true multi-slide carousel that preloads adjacent events' data; CAP-2 reuses Carousel chrome only over the existing single-item async navigation.
- (non-goal) Not adding in-popover search (e.g. shadcn Command) to the FilterHub dropdowns at this time -- current option-list sizes don't justify it; noted as a future enhancement only.
- (non-goal) Not changing the backend data model, GraphQL API, or any server-side logic -- this spec is presentation-layer only.
- (non-goal) Not reopening or renegotiating any other epic's scope (e.g. Epic 3's active sprint-change-proposal, Epic 6 widget work in progress).

- (assumption) Assumed the FilterHub Type/Category option lists remain small enough that a plain toggle/checkbox list inside a Popover (no search) stays usable; revisit if list length grows substantially.
